## Authenticated live smoke test

The supplied QA credentials were entered interactively and were not persisted
or printed. Authentication succeeded against local Supabase. The selected real
project was `QA E2E Export dan Evidence 2026-08-23`.

| Check | Observed result |
|---|---|
| Ready papers | 2 |
| Research-question table rows | 1 |
| Methodology table rows | 1 |
| Matrix cells | 7 |
| Matrix statuses | `edited`, `verified` only |
| Duplicate Matrix paper/parameter pair | 0 |
| Research Gap candidates | 2 |
| Gap decision branches | `rejected` then `accepted`, both HTTP 200 |
| Persisted final gap decision | `accepted` |
| Structured PDF | HTTP 200, 45,233 bytes, 2 pages |
| Chatbot | Answer returned with 1 evidence source |

The original chatbot implementation exposed a real defect: the Gemini SDK's
default retry policy could hold a request for more than two minutes. A trivial
primary-model request also reproduced provider `504 DEADLINE_EXCEEDED` while
the lite fallback returned successfully. The fix:

- bounds each provider attempt to 12 seconds;
- disables hidden SDK retries for chat;
- selects the faster fallback model first;
- selects only question-relevant academic parameters;
- limits each cell to one concise evidence context.

After the fix, the complete authenticated smoke test, including chat, completed
successfully and the chatbot returned an evidence-linked answer.

## Browser interaction limitation

The local release app is healthy and returns HTTP 200. Browser-control QA could
not be completed in this iteration because the selected in-app browser tab was
already on its internal `data:` connection-error page from an earlier attempt.
Its security policy rejected every subsequent navigation or DOM action on that
internal URL and explicitly prohibited switching to a workaround browser
surface. The browser was not bypassed.

Consequently, this report does **not** claim a new direct click-through browser
run for the 2026-08-25 UI. UI interaction is verified through 15 widget tests,
while authentication, project selection, real data, both gap branches, chatbot,
and download behavior are verified through the live owner-scoped API. A fresh
controllable browser tab is the only outstanding manual QA step.
